# Создание векторного индекса базы знаний

## Описание данных
Наша библиотека основана на фандоме Смешариков, основные параметры:

1) 32 файла
2) текст на русском языке
3) 4 типа файлов: описание персонажа, описание дома персонажа (рабочее место), описание сюжета серии, описание мира


## Эмбеддинг модель

Наши данные на русском языке, поэтому модель эмбеддинга должна быть к нему адаптирована.

### Варианты моделей:
1) [Модель all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
2) [paraphrase-multilingual-MiniLM-L12-v2] (https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)
3) [sergeyzh/rubert-tiny-turbo](https://huggingface.co/sergeyzh/rubert-tiny-turbo)

### Сравнение

Проверим модели путем проверки сходства векторов (cosine_similarity) на разных предложениях. Для этого я подготовил [скрипт](/scripts/embedding-models/compare-embedding-models.py)

Подготовка:
```bash
pip3 install -U sentence-transformers
```

Запуск:
```bash
python3 scripts/embedding-models/compare-embedding-models.py
```

## Разбиение по чанкам

### Установка инструментов

Для чанкинга нам понадобится библиотека LangChain.

Установка:
```bash
pip3 install -U langchain-text-splitters
```

### Стратегия чанкинга
Для чанкинга нам понадобится:
1) очисить текст от мусорных символов типа wiki разметки (* , ===, ---) .
   Это необходимо для устранения шума при эмбеддинге и сокранения токенов
2) добавить к тексту "хлебные крошки" - навигацию к источнику по файлу (имя файла -> раздел -> подраздел)
3) добавить метаданные
   Например, тип файла (персонаж, серия, страна, рабочее место), название файла, количество символов, количество слов
4) Разделить embed_text - для эмбеддинга, text - для цитирования
5) Запустить чанкинг и получить результат в chunks.jsonl

### Определение размера чанка
Наша модель paraphrase-multilingual-MiniLM-L12-v2 имеет контекстное окно 128 токенов. 

Для русского языка 1 слово ~ 1.5 - 2 токена.

Служебные токены <s>, </s> - 2 токена

Хлебные крошки ~ 15-20 токенов.

Итого остается 108 токенов. 108 / 1.5 = 72 ~ 70 слов потолок

Для русского языка средняя словоформа 6 символов + пробел = 7 символов.

Итого получаем: 70 слов x 7 символов = 490 символов ~ 500 символов в чанке.
Оверлап 10-20% от chunk_size = 80 слов

**Итого: chunk_size=500, overlap=80**

### Скрипт для чанкинга

Для чанкинга я подготовил [скрипт](/scripts/chunking/chunk_kb.py)

В нем проводится:
1) очистка текста от wiki форматирования (---, ===) для устранения шума
2) парсинг метаданных
   1) название файла
   2) тип файла (описание рабочего места, персонажа, серии, страны)
3) добавление для embed_text "хлебных крошек" с указанием, откуда взят фрагмент
4) добавление текста в блок text для референса
5) разбиение на чанки
   1) первый этап - разбиение по хедерам
   2) второй этап - разбиение по чанкам текста после хедера, если он больше chunk_size
6) сохранение чанков в файл [chunks.jsonl](scripts/chunking/chunks.jsonl)

## Создание индекса и сохранение в Chroma DB

### Развертывание Chroma DB

Базу данных я поднял локально с помощью [docker-compose.yml](docker/docker-compose.yml)
Это простая конфигурация Chroma DB

### Индексация и сохранение в базу

Индексации и сохранение в базу происходят с помощью скрипта [build_index.py](scripts/indexing/build_index.py)

В этом скрипте:
1) загружаются чанки из [chunks.jsonl](scripts/chunking/chunks.jsonl)
2) каждый чанк проходит проверку на длину токенов, выводится процент чанков, превысивших лимит
3) чанки кодируются с помощью paraphrase-multilingual-MiniLM-L12-v2
4) закодированные чанки сохраняются в коллекцию в Chroma DB. (по дефолту при выполнении скрипта коллекция перезаписывается)

После первого запуска скрипта, я увидел, что достаточно много чанков не укладывались в лимиты по токенам, поэтому я **снизил chunk_size до 300** и заново сгенерировал их

## Семантический поиск

Для поиска используется скрипт [search.py](scripts/search/search.py)


Он принимает на вход вопрос в виде аргумента, далее кодирует его в вектор, ищет топ-K совпадений в базе и выводит их информацию. Число кандидатов задаётся аргументом `-k` (по умолчанию 4).

Пример вызова с вопросом и количеством кандидатов:

```bash
python3 scripts/search/search.py "кто лучший друг джависта?" -k 3
```
